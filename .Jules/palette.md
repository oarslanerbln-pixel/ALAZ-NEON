## 2026-04-07 - Custom Button Accessibility
**Learning:** When using Framer Motion to create interactive `motion.div` elements that act as buttons (like `TiltCard`), they lack default keyboard accessibility. Adding `role="button"`, `tabIndex={0}`, `onKeyDown` handlers for 'Enter' and 'Space', and Tailwind `focus-visible` classes is essential for screen readers and keyboard navigation.
**Action:** Ensure all custom interactive `div` or `motion.div` components meant to behave like buttons include proper ARIA roles, keyboard event handlers, and visible focus states.
## 2026-05-03 - Form Accessibility Pattern\n**Learning:** When adding ARIA attributes to dynamically rendered components (like Framer Motion animations) or handling inputs that depend on external state, standard DOM association (`htmlFor` with `id`) handles label association properly, while `aria-live` regions correctly manage screen reader focus without interrupting state logic. Also, when retrieving JSX from large files in bash, standard `cat` output truncates, so `sed -n` with specific line ranges is strictly required.\n**Action:** Use specific `sed -n` ranges to grab exact JSX, and consistently apply `htmlFor`/`id` linking alongside dynamic `aria-invalid` state for forms.

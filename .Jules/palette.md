## 2026-04-07 - Custom Button Accessibility
**Learning:** When using Framer Motion to create interactive `motion.div` elements that act as buttons (like `TiltCard`), they lack default keyboard accessibility. Adding `role="button"`, `tabIndex={0}`, `onKeyDown` handlers for 'Enter' and 'Space', and Tailwind `focus-visible` classes is essential for screen readers and keyboard navigation.
**Action:** Ensure all custom interactive `div` or `motion.div` components meant to behave like buttons include proper ARIA roles, keyboard event handlers, and visible focus states.
## 2024-05-03 - Next.js Monorepo Setup and Playwright Verification
**Learning:** Next.js build infers workspace root incorrectly when stray `pnpm-workspace.yaml` files exist in child directories (`apps/frontend`). It also requires `turbopack: {}` explicitly in `next.config.ts` to clear validation warnings. Also, `next-pwa` throws typescript type errors with `NextConfig` without a typecast (`withPWA(nextConfig as unknown as Record<string, unknown>)`). Finally, Framer Motion requires `page.wait_for_timeout()` when taking Playwright screenshots of dynamically added elements wrapped in `<AnimatePresence>`.
**Action:** Always delete child `pnpm-workspace.yaml` files in monorepos, use the explicit typecast for `next-pwa`, include `turbopack: {}` in Next 15+ root config, and add explicit timeouts in Playwright scripts when capturing UI state dependent on animations.

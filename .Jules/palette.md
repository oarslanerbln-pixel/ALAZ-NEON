## 2026-04-07 - Custom Button Accessibility
**Learning:** When using Framer Motion to create interactive `motion.div` elements that act as buttons (like `TiltCard`), they lack default keyboard accessibility. Adding `role="button"`, `tabIndex={0}`, `onKeyDown` handlers for 'Enter' and 'Space', and Tailwind `focus-visible` classes is essential for screen readers and keyboard navigation.
**Action:** Ensure all custom interactive `div` or `motion.div` components meant to behave like buttons include proper ARIA roles, keyboard event handlers, and visible focus states.
## 2026-05-10 - Explicit Labeling and Dynamic Error ARIA Attributes
**Learning:** Found an accessibility pattern specific to forms and inline validation warnings. Simple `<label>` text above inputs is insufficient without explicit `htmlFor` and matching `id`s, leaving screen readers disconnected from the input context. Additionally, dynamic validation messages (like "Yanlış Harf!") that appear conditionally within `motion` animations are inherently invisible to assistive technologies if they lack `role="alert"` and `aria-live="assertive"`.
**Action:** Always link `<label>` and `<input>` using `htmlFor` and `id`, even for auto-generated lists. When rendering transient state messages or errors within conditional blocks (e.g., inside `<AnimatePresence>` or specific `motion` components), explicitly attach `role="alert"` and `aria-live="assertive"` so that screen readers announce these visual warnings immediately to the user.

## 2026-04-07 - Custom Button Accessibility
**Learning:** When using Framer Motion to create interactive `motion.div` elements that act as buttons (like `TiltCard`), they lack default keyboard accessibility. Adding `role="button"`, `tabIndex={0}`, `onKeyDown` handlers for 'Enter' and 'Space', and Tailwind `focus-visible` classes is essential for screen readers and keyboard navigation.
**Action:** Ensure all custom interactive `div` or `motion.div` components meant to behave like buttons include proper ARIA roles, keyboard event handlers, and visible focus states.
## 2026-04-07 - Interactive Element Feedback in Dark Themes
**Learning:** In the MediSade high-contrast dark theme, standard browser focus states and unstyled disabled buttons are nearly invisible, significantly degrading accessibility. Explicitly applying Tailwind's `focus-visible:ring-4 focus-visible:ring-yellow-400 focus-visible:outline-none` is essential for keyboard navigation, and adding `disabled:cursor-not-allowed` provides necessary visual feedback for inactive buttons.
**Action:** Ensure all new interactive elements (buttons, links) explicitly implement high-contrast `focus-visible` rings and, where applicable, `disabled:cursor-not-allowed` classes to maintain WCAG 2.1 AA compliance in High Contrast Mode.

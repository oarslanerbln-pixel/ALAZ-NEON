## 2026-04-07 - Custom Button Accessibility
**Learning:** When using Framer Motion to create interactive `motion.div` elements that act as buttons (like `TiltCard`), they lack default keyboard accessibility. Adding `role="button"`, `tabIndex={0}`, `onKeyDown` handlers for 'Enter' and 'Space', and Tailwind `focus-visible` classes is essential for screen readers and keyboard navigation.
**Action:** Ensure all custom interactive `div` or `motion.div` components meant to behave like buttons include proper ARIA roles, keyboard event handlers, and visible focus states.

## 2026-04-09 - Form Accessibility Attributes
**Learning:** In highly stylized or custom game UIs, standard form accessibility is easily overlooked. Explicitly linking labels to inputs using `htmlFor`/`id` pairs, exposing validation error messages using `role="alert"` and `aria-live="assertive"`, and marking inputs as `aria-invalid` ensures these heavily visual apps remain understandable to screen reader users without changing their appearance.
**Action:** When inspecting forms, ensure `htmlFor` and `id` bindings exist. If errors can dynamically appear, wrap them in `role="alert"` and `aria-live="assertive"` containers. Use `aria-invalid` to convey semantically incorrect inputs.
